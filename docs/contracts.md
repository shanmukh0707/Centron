Nobody edits inside another person's folder. There are zero shared source files

### The one rule that actually matters: contract changes

The schema is the only thing that can silently break someone else's work.

1. **Only Shan edits `schemas.py`.** If Android needs a field, ask, do not add.
2. Any schema change **bumps `v`** and regenerates `contract.json`.
3. Shan posts in the group chat: *"contract v2, field X added, regenerate."*
   No silent pushes.
4. Android regenerates Kotlin data classes from the new `contract.json`.
5. Adding an optional field is not breaking, provided the decoder has
   `ignoreUnknownKeys = true`. Renaming or removing a field is breaking and
   should not happen after tonight.

If the contract holds, running ahead is safe. That is the entire point of having
spent Hour 0 on it.

## CONTRACT 1: EVENT SCHEMA (WebSocket)
*Android owner and backend owner both build against this.*

### Envelope, every frame, both directions

```json
{ "v": 1, "type": "event", "seq": 1042, "ts": "2026-09-20T14:03:11.482Z", "data": {} }
```

| field | type | notes |
|---|---|---|
| `v` | int | schema version, starts at 1, bump on breaking change only |
| `type` | string enum | server to phone: `event`, `heartbeat`, `audio_ready`, `action_update`, `hello`. phone to server: `ack`, `approve_action`, `resync` |
| `seq` | int | monotonic, server-global, persisted, survives restart |
| `ts` | string | RFC3339, UTC, milliseconds, always `Z`. Server-authoritative |
| `data` | object | shape determined by `type` |

Heartbeats are their own `type`, never a low-severity event. If they flow through
the event path they hit Room, the TTS queue and the event list, and get filtered
back out under time pressure.

### `type: "event"` data

```json
{
  "event_id": "0192f3b1-7c4a-7b21-9c3e-1f2a3b4c5d6e",
  "signature": "ssh.auth.brute_force",
  "severity": "high",
  "title": "SSH brute force from 203.0.113.44",
  "internal_log": "47 failed password attempts for root from 203.0.113.44 in 38s",
  "tts_summary": "An external address is brute forcing SSH on your main server.",
  "confidence": 0.82,
  "entities": {
    "src_ips": ["203.0.113.44"],
    "dst_hosts": ["fileserver-01"],
    "users": ["root"],
    "ports": [22]
  },
  "source": { "kind": "auth_log", "collector": "sentinel-01", "raw_count": 47 },
  "window": { "start": "2026-09-20T14:02:33.000Z", "end": "2026-09-20T14:03:11.000Z" },
  "audio": {
    "status": "ready",
    "audio_id": "a_8f2c",
    "url": "https://sentinel.lan:8443/audio/a_8f2c.mp3",
    "mime": "audio/mpeg",
    "duration_ms": 3400,
    "sha256": "...",
    "cache_key": "tts:v1:9a3f..."
  },
  "escalation": {
    "escalated": true,
    "gate": "correlation",
    "reason": "3 distinct sources in window",
    "state": "answered",
    "verdict": "Coordinated scan, not targeted."
  },
  "action": {
    "playbook": "block_ip",
    "params": {},
    "status": "pending_approval",
    "requires_approval": true,
    "expires_at": "2026-09-20T14:08:11.482Z",
    "approval_id": "ap_71c3"
  },
  "reviewed": false
}
```

Locked decisions:

- `event_id` is UUIDv7. Time sortable. Join key between server SQLite and phone
  Room, and the Room primary key, so replays dedupe for free.
- **`severity` has four values: `info`, `low`, `high`, `critical`.** Each is
  defined by phone behavior, not by feel. `info` logs silently and never speaks.
  `low` queues TTS behind current playback. `high` interrupts the queue.
  `critical` interrupts plus alarm tone plus haptic.
- `entities` is structured and is never re-parsed out of prose. This is what
  makes the "Block this IP" button possible without regexing `internal_log`. If
  the phone ever regexes a narration string, the contract failed.
- Real values go to the phone, tokens do not. Redaction protects the model and
  the Claude API, not the admin. Python resolves `HOST_A` back to `fileserver-01`
  before serialization. Only `tts_summary` stays value-free, by construction.
- Audio is referenced, never inlined. No base64 in the frame. The phone fetches
  `url` over the same TLS session with the same bearer token. `cache_key` is a
  hash of the phrase so repeated lines hit the phone cache and spend no
  ElevenLabs credits.
- `audio` is nullable and `audio.status` is `ready | pending | failed |
  suppressed`. Never block an event on TTS. Ship JSON immediately. Late audio
  arrives as `type: "audio_ready"` carrying the same `event_id`.
- `reviewed: false` is the fail-closed flag. Phone renders an unreviewed badge.

### `type: "heartbeat"` data

```json
{
  "interval_s": 10,
  "uptime_s": 4127,
  "last_event_seq": 1042,
  "queue_depth": 0,
  "pipeline": {
    "log_source": "ok", "ollama": "ok", "tts": "degraded", "claude": "unreachable"
  }
}
```

- Every 10s. Phone amber at 15s, red at 25s.
- Red state is driven by the heartbeat gap, not by OkHttp socket callbacks. A TCP
  socket can sit open and dead for minutes, which is exactly the stale all-quiet
  screen the non-negotiables forbid.
- `last_event_seq` lets the phone notice it missed frames during a reconnect and
  send `resync`. Without it the app loses events silently.
- `pipeline` is per subsystem so the UI can be amber instead of binary.

### Phone to server

- `ack { seq }`, optional, delivery accounting
- `approve_action { approval_id, event_id, decision: "approved"|"denied", biometric: bool }`
  (as in `contract.json` and `samples/approve_action.json`; `event_id` must match
  the approval's event). Note: `biometric: bool` is a claim by the app, not a
  signed assertion; the pinned cert plus the pre-shared token is what actually
  authenticates the client.
- `resync { since_seq }`, replays buffered events oldest first, capped at 200

Server rejects late approvals. If `expires_at` has passed, reply
`action_update { approval_id, status: "expired" }` and the phone must show it.

## CONTRACT 2: PLAYBOOK CATALOG
*Backend owner. Android owner only needs the names and `requires_approval`.*

Common to all: `playbook` (enum), `reason_signature`, `requested_by:
"model"|"operator"`, `ttl_sec`. Targets arrive from the model as tokens. Python
resolves them.

### watch
- Params: `subject { type: ip|host|user|signature, value }`, `duration_sec`,
  `threshold { count, window_sec }`, `escalate_on_hit: bool`
- Caps: `duration_sec` max 86400. Max 50 concurrent. No breadth cap, read only.
- Auto-executes. Auto-expires.
- Dedupe on `(type, value)` or the model stacks a dozen watches on one IP during
  a flood.

### notify_only
- Params: `channel: push|tts|silent`, `severity_override` (may only lower)
- Caps: 1 per signature per 5 min, 20 per hour globally.
- Auto-executes. Nothing to expire.
- No free-text field. The spoken line is `tts_summary` and nothing else.

### rate_limit
- Params: `target_ip` or `target_cidr`, `protocol: tcp|udp|any`, `port`
  (optional), `limit_conn_per_min`, `duration_sec`
- Caps: auto `duration_sec` <= 1800, approved <= 7200. `limit_conn_per_min` floor
  of 10 so a limit cannot silently become a blackhole. Auto path is `/32` only.
  Broadest ever allowed is `/24`.
- Auto-executes at `/32`. Auto-expires.
- This is the default auto action, not `block_ip`. "We throttle first and block
  only with your thumbprint" is the better product and the better pitch line.

### block_ip
- Params: `target_ip` or `target_cidr`, `direction: inbound|both`, `duration_sec`
- Caps: auto <= 3600, approved <= 86400. Auto path requires a single public
  `/32`. Anything RFC1918, anything broader than `/32`, or anything touching
  PROTECTED_ASSETS (gateway, Sentinel host, admin workstation, the phone)
  requires biometric. Hard floor at `/24`, never broader.
- Auto-executes only under the above. Auto-expires, mandatory.

### isolate_host
- Params: `host_id` (one internal asset, never a CIDR), `mode:
  quarantine_vlan|drop_all|allow_mgmt_only`, `duration_sec`, `allow_list`
- Caps: exactly one host per call. `duration_sec` <= 3600, extension needs fresh
  approval. Never against a protected asset.
- Never auto-executes. Biometric always. Auto-expires.
- The expiry must live in the enforcement layer (nft rule with a timeout, or a
  cron-installed restore), not in an app-level reaper. Otherwise a crashed
  Sentinel leaves a host isolated with nothing left alive to release it.

### revoke_session and snapshot_evidence
In the enum, param models exist, execution may be cut for time. Keep them in the
catalog either way so the catalog shown to judges is the catalog designed.

### Global controls, not per action
Per-action caps do not bound the real risk, which is volume.
- Max 10 auto-executed actions per hour.
- Circuit breaker: if more than 5 fire in 10 minutes, auto-execution suspends and
  everything falls back to `pending_approval` until a human resets it.

## CONTRACT 3: OLLAMA OUTPUT SCHEMA
*Backend owner only.*

The model returns only this. Strict JSON, `format: "json"`, unknown keys
rejected.

| field | type | constraints |
|---|---|---|
| `internal_log` | string | 1 to 600 chars, tokens only. Reject on IP literal, MAC or `@` |
| `tts_summary` | string | see below |
| `severity` | enum | `info` \| `low` \| `high` \| `critical` |
| `confidence` | float | 0.00 to 1.00, advisory only |
| `escalate` | bool | |
| `escalate_reason` | string or null | non-empty and <= 200 chars when `escalate` is true, must be null when false |
| `action` | enum | exactly one catalog name. No `none` value, `notify_only` is the no-op |
| `action_params` | object | validated per action as a discriminated union, targets are tokens |

### tts_summary constraints
- Exactly one sentence. Max 20 words, max 140 chars.
- No IP literals, no MACs, no usernames, no `@`, no port numbers.
- No tokens either. Require role nouns: "a workstation", "your file server",
  "an external address", "an admin account".
- On violation: one retry naming the violation, then fall back to a
  Python-generated template from `signature` plus `severity`. A TTS validation
  failure must never kill the event.

### The framing that matters most
The model emits three strings, one float, one bool, two enums and a params
object. Nothing else. Every fact comes from the parser: `event_id`, `ts`,
`signature`, `entities`, `raw_count`, `window`, `source`. If the model is ever
allowed to report a count or an IP, an attacker who controls log text controls
what the admin hears.

Retry policy: 2 attempts on schema failure, then a deterministic fallback event
with `action: notify_only`, `escalate: true`, `gate: schema_failure`. Never drop.

## TWO EXECUTION LANES — everyone should know these

**Lane 1, playbook actions: auto-executes.** The model selects a playbook name
and fills typed parameters. Python validates against the allowlist and caps,
resolves tokens, and executes. Reversible low-blast-radius actions run
automatically and auto-expire. Destructive ones require biometric approval.

**Lane 2, generated scripts: never auto-executes.** The local model may draft a
remediation script. The app displays it, a human reviews and runs it. Generated
text never reaches an executor, because the log text that produced it is
attacker-controlled.
